# 三个监控功能的边界与会话规则

| 功能 | 观察目标 | 依赖 | 时间语义 | 独立面板 / 配置 |
|---|---|---|---|---|
| 串口监控 | 端口内核 I/O | 自研 SerialMonitor 驱动及其原安装/签名流程 | 内核记录时间 | serial-monitor / 原配置 |
| 进程串口监控（API Hook） | 用户选定的一个进程中的串口 API 调用 | 匹配目标架构的 Hook 组件 | API 请求/完成时间 | process-monitor / ProcessMonitor |
| USB 抓包（USBPcap） | USB 设备、接口及端点上的传输 | 实时捕获需要 USBPcap 驱动；离线分析无需驱动 | USB 捕获时间 | usb-capture / UsbCapture |

两个新功能有各自 View、ViewModel、配置、错误消息、记录和启停操作；不依赖 SerialMonitorService 或其驱动安装服务。每个新功能首期最多一个活动会话。三个导航按钮分别打开/隐藏自己的面板；隐藏和重新打开不能重建或停止会话。一个组件缺失、权限失败或采集端退出只改变所属功能的状态。

API Hook 不跟踪子进程，不声称捕获所有系统调用或线路时间。受保护进程、未验证架构、绕过覆盖 API 的路径不支持。附加前已打开句柄必须单独验证；未确认时提示重新打开，不能假定覆盖。USB 不伪造 PID/COM 口字段；未知厂商载荷仅展示 USB 原始记录。

## 生命周期约束

- 启动成功生成新的会话 ID；配置中只保存选择偏好，不保存 PID、活动状态或恢复采集。
- 按进程启动实例、句柄世代识别 API 流；按设备连接实例、接口、端点识别 USB 流。数值复用不能复用旧流。
- 启动中/运行中拒绝重复启动或附加；停止不结束业务进程；旧会话迟到事件不进入新会话。
- 挂起 I/O 未完成时不卸载仍会被调用的 Hook 模块；取消不是完成，只有真实完成结果可以确定实际字节数。
- 进程退出、采集断开、溢出、失败、截断、序号缺口均形成数据边界；不得把断点前后的残片组合为完整协议帧。

## 共用处理边界

只共享无 UI 的字节格式化、显示筛选、显式定长组帧、现有协议解析服务和导出编码。输入包含来源、会话、流、方向、原始记录 ID、时间语义、完整性；来源专有原始记录独立保留。组帧按完整流标识与方向隔离，派生帧保留全部原始记录引用。控制记录、写入尝试、失败记录不直接参与业务组帧。显示筛选在组帧之后执行，以免隐藏部分记录伪造连续流。

## 验收场景

1. 三个入口分别打开独立面板；API Hook 或 USB 未安装仍能使用原串口功能。
2. 两个新功能偏好保存并重启恢复；相互保存不覆盖对方配置；不会自动恢复采集。
3. 运行时切换、隐藏面板保留会话；单独停止、故障不改变其他功能。
4. 混合来源、会话重启、双向交错、句柄/设备复用及数据缺口不串帧；原始记录可追溯。
5. 原监控驱动、端口选择、记录及 CSV 导出回归通过。

本文件规定实现契约；捕获可用性以各功能实测矩阵为准。当前 USB 页面仅提供独立入口和偏好，不提供采集能力。
