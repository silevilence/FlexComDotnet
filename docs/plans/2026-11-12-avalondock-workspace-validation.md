## 实现边界与使用方式

- `DockWorkspace` 持有每个页面的内容实例，AvalonDock 管理布局。业务层没有引入 WPF／AvalonDock 依赖。旧 `MultiZoneLayout`、`FloatingPanelWindow`、`CollapsiblePanel` 已移除。
- 收发为不可关闭的中央文档；连接配置、指令、自动回复、脚本、串口监控、进程监控、USB 抓包、波形、日志为可隐藏工具。工具可拖入文档区，收发也可分组、浮动。
- 隐藏或拖动不停止通信、脚本或采集。停止仍使用各功能原有按钮。USB 抓包页面保留原项目“尚未实现”的能力说明，本次没有新增 USBPcap 采集实现。
- 左侧导航和“视图”菜单找回并激活已有工具；设置中的可见性开关仍有效。`Ctrl+Tab`／`Ctrl+Shift+Tab` 切换页面；`Alt+V`／`Alt+W` 打开视图／窗口菜单，窗口菜单提供浮动、分组、停靠和隐藏；F12 沿用原有调试开关。
- “恢复默认布局”恢复位置，同时保留当前页面实例和未保存文档。关闭编辑文档或退出应用会提示保存、放弃或取消；写入失败时保留草稿。
- 脚本编辑器每个脚本一个文档缓冲区，列表选择变化不会覆盖其他编辑页；关闭文档只释放编辑器订阅，不停止共享脚本引擎。
- 协议管理和 Tx 组帧各保留一个文档；每次 Rx 解析可打开一个独立文档以比较记录。设置、更新、校验计算器、依赖确认继续采用原有对话框。

## 布局文件与迁移规则

- 新文件为配置文件同目录下的 `workspace-layout.xml`，格式版本 `FlexComVersion="1"`。采用先写临时文件、再替换的方式保存。
- 布局只保存页面 ID 和布局元数据，不保存发送内容、接收数据、脚本草稿或协议测试输入。已存在的脚本和协议管理／Tx 页面可以按 ID 重新创建，内容从业务服务加载。Rx 临时解析文档不跨进程恢复。
- 首次迁移保留 `config.json.before-docking`。旧区域、顺序、可见性、区域尺寸和浮动位置可映射；旧版逐面板折叠无法与页签组一一对应，采用“优先选择展开页；旧区域折叠或全组均折叠时自动隐藏整组”的规则。
- 无法读取、格式损坏、重复 ID 或不支持的版本回退默认布局；损坏原件尽可能保存在 `.invalid` 文件中。未知页面被跳过，新注册的工具仍可从入口找回。
- 非有限或明显超出当前虚拟屏幕范围的浮动坐标会重定位到主屏可见区。多屏空洞、显示器移除和跨 DPI 的实际坐标行为仍需要实机补验。

## 自动验证

执行命令（复用本地 NuGet、SDK 和已有资源；未重新下载测试环境）：

```powershell
dotnet test tests/FlexComDotnet.Tests --no-restore -p:BuildSerialMonitorDriver=false -p:BuildProcessHook=false --verbosity quiet
dotnet publish src/FlexComDotnet/FlexComDotnet.csproj -c Release --no-restore --self-contained false -p:BuildSerialMonitorDriver=false -p:BuildProcessHook=false -o <临时发布目录>
```

原生驱动／Hook 代码未修改，上述参数跳过其构建；这些结果不代表驱动安装或实机采集验收。

新增验证主要集中在 `DockWorkspaceTests`、`DockLayoutStoreTests`、`ProtocolDocumentTests`、`LuaEditorThemeTests`，并补充脚本和协议 ViewModel 回归：

- 收发、连接、日志、ScottPlot 四个真实页面及十个主页面的内容实例保持。
- 100 次隐藏／显示、10 次布局恢复期间注入 100 个两字节帧：恰好 100 条记录、200 字节，发送草稿不变，没有调用关闭通信接口。这是受控服务输入，不是物理串口或驱动压力测试。
- 使用 AvalonDock 实际命令完成纵向分组后再做横向嵌套分组，保存／恢复后保留三个文档窗格；显式启用 `AllowMixedOrientation`。
- 旧区域整体移动、排序、展开页选择、隐藏工具恢复、新增／未知页面、文档 ID 解析、配置备份、损坏文件和版本拒绝。
- 文档单实例、取消关闭、关闭释放、默认布局重置不丢缓冲区；协议“保存／放弃／取消”及保存失败四种组合。
- 使用真实协议解析器构建 `AA 55`，Rx 解析成功；ASCII `A` 的追加回填得到 Hex `41 AA 55`，覆盖回填得到 `AA 55`。
- 协议配置写入失败时保留编辑状态及原解析器定义；脚本写入失败时保留脏缓冲区。
- 协议页在 320×200 DIP 容器内提供横纵滚动范围；Lua 高亮切换主题时更新颜色并保留文本。
- 独立 `--data-directory` 覆盖配置、命令数据库、脚本和日志，避免验收修改正常工作数据。

现有 `SkiaSharp.Views.WPF` 的 NU1701 和测试中的 CS8625 警告仍存在，未新增对应依赖问题。所用 Dirkster.AvalonDock、VS2013 主题、XML 序列化包均为 **5.0.1**；本地包元数据提供 `net10.0-windows7.0` 资产，AvalonDock 包含 Ms-PL 许可文件。

## 实际 UI 观察

复用同一临时数据目录和本地构建资源。每轮发现问题后关闭测试程序，完成修复再复验；未安装驱动，未开启真实采集。

- 连接配置从工具区拖为浮动窗口，再拖入中央文档区；页面内容保留。
- 脚本从列表“编辑”进入中央文档，输入草稿后关闭出现三选项提示；取消后草稿保留，保存后预览同步，重启后从文件恢复已保存内容。
- 协议管理通过原入口打开文档；小停靠区域可拖动整体滚动条访问超出区域的内容。
- “窗口”菜单执行垂直分组成功，脚本与协议并排；文档浮动成功；主窗口及浮动文档深浅主题同步。
- `Alt+W` 可展开菜单；默认布局恢复入口可用；复杂布局的嵌套方向补充由自动测试验证。
- 已修复验收中发现的全局叶子菜单模板缺少弹出层、动态菜单清空造成关闭、协议页裁切、浅色 Lua 颜色及协议保存结果未检查问题。
- 正常退出主窗口后浮动文档随之关闭；核验无剩余测试窗口／进程，临时验收目录没有 `crash.log`。
